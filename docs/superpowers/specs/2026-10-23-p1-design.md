# P1：Pointer Head + Backbone LoRA

用户已批准七组实验路线，本轮明确要求运行 P1，并指定可使用 26 服务器的 4090。P1 保持 P0 的 Pointer 结构和 G1 的 LoRA 范围，联合训练二者。常规实现与资源选择由执行者完成，不重复申请已有授权。

## 固定科学协议

- 从同一份原始 Qwen3.5-0.8B 初始化，不继承 P0 Head、G1 adapter 或 G2 权重。
- Head 使用与 P0 对应 seed 相同的独立随机初始化规则（重新生成，非加载旧权重），避免 LoRA 初始化消耗 RNG 后改变 Head 起点；记录初始 Head 哈希。LoRA 初始化顺序沿用 G1。
- 数据 revision、960/120/120/400 case 划分、B0 完整提示和五题独立因果输入保持不变。仅 gold argmax 硬候选交叉熵；calibration 不访问。
- Pointer 完全沿用 P0：最后有效输入 token 为 query，候选文本最后非空字符所在 token 为 key；两个无 bias 1024→128 FP32 Xavier 投影，scaled-dot 匹配，只归一化有效候选。262,144 个 Head 参数，不新增 token／归一化／位置参数。
- LoRA 沿用 G1：r16、alpha32、dropout0、186 个相同 Linear 目标，10,822,656 个 FP32 adapter 参数；原始 752,393,024 个 BF16 文本参数及原生 FP32 rotary buffers 冻结，保留原 embedding／LM Head 绑定。合计 11,084,800 个可训练参数。
- 训练直接调用原生文本 Backbone 并保留 query/key 的梯度，绕过 LM 词表投影。不得复用 P0 的 no_grad／detach 特征提取，也不得缓存训练后的隐藏特征。仅缓存固定 token IDs、候选位置和源身份。
- 训练时 Backbone 可使用 BF16 autocast；原生 eval 跟随 B0/P0/G1，不开启 autocast。进入 Pointer Head 时必须显式关闭 autocast，并使用保持计算图的 FP32 query/key。通过 dtype／梯度测试确认，避免 FP32 参数在外层 autocast 中被隐式改成 BF16 运算。
- AdamW 两组：LoRA LR2e-4（G1），Head LR1e-3（P0）；共同 WD0.01、betas0.9/0.999、eps1e-8，foreach=False；clip1.0 作用于全部可训练参数。各组 23 步 warmup 再 cosine。
- Seeds42/43/44，每 seed3 epochs、450 更新、每步32题，复用原 epoch_groups 顺序。候选 micro8×acc4；若 train-only 4090 预检内存不通过，可在正式冻结前降为 micro4×acc8，并明确记录实际配置。无 test 驱动调整。
- 每个 seed 的随机 Head + zero-LoRA epoch0 必须在本机实测 dev，不能复制 B0/P0 既有 dev。用 dev Hard NLL 最小值在 epochs0..3 选模，同分取更早步骤。三个选择全部锁定后才各进行一次完整 test。
- 训练可用既有 project-local FLA DeltaNet chunk，normalization/convolution 保留原生；全部 dev/test 原生后端、未合并 adapter，包含分词/位置映射/传输/Backbone/Head/概率转 CPU 的同步端到端计时。

## 完整性与恢复

- 新增独立 P1 模块／入口／配置，不修改 B0/G1/G2/P0 已归档的任何科学源码。新脚本复用既有数据、Pointer 定位/Head、LoRA 注入、调度、指标及 bootstrap。
- 原参数和所有 buffer 冻结哈希包括 dtype/shape/值，排除 adapter；训练开始/各阶段后核对；两个新投影均更新，adapter 的 B 更新、A 在非零 B 后可获梯度。禁用 LM Head 调用可通过 trap 证明。
- 不可变 checkpoint 同时包含 adapter、Head、config 与 optimizer/scheduler/Python/NumPy/Torch/CUDA RNG/progress，完整哈希 manifest 后原子更新 latest。保存 step0、2、每50步、各 epoch；保留初始/各 epoch/最新。严格验证联合状态，不能混用不同步骤的 Head 和 LoRA。
- resume 校验配置、来源源码快照、模型、raw/splits、runtime构建、FLA和本机预检；独占运行 lease。恢复只从完整步骤，归档/checkpoint后历史后重放；部分 heldout 结果拒绝隐式重跑。已完成结果不重跑。
- 元数据记录机器/显卡 UUID/驱动/物理GPU0→cuda0、Conda/Python/Torch/Transformers/PEFT/Triton/FLA指纹与完整 SHA。dev/test 预测和原始 candidate scores 保持已有 schema，原始选模与 summary 不被后处理改写。

## 硬件和环境

26（alg26，192.168.0.26）GPU0 为 24GB RTX4090，初始空闲；GPU1 的4080正在被其他任务占用，不干预；GPU2为另一个空闲4090，本轮不要求多卡训练。20服务器不启动 GPU 工作。

26 现有 Conda 环境版本不足以直接使用 Qwen3.5。在仓库 .runtime 下建立专用 Conda prefix，避免改动共享已有环境。目标 Python3.12、Torch2.9.0及可用于4090的CUDA12构建、与旧实验相同 Transformers5.14.1／PEFT版本。环境选择以实际原生前向和 FLA 梯度预检通过为准，不修改系统驱动。CUDA12 minor compatibility 对 PTX 有限制，不能仅凭版本号宣布可用：[NVIDIA官方说明](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)、[PyTorch构建列表](https://pytorch.org/get-started/previous-versions/)。

已有 B0/G1/G2/P0 使用5090，不直接将4090上的P1延迟与旧延迟解释为架构差异；准确率比较同样注明硬件/运行栈差异及固定配方限制。科学结论与部署成本的公平比较分开报告。
